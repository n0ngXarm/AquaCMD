# AQUA COMMAND v0.4 independent review

Reviewed frozen committed range `baseline-v0.3..d839024` (G0–G4), after reading all of `AGENTS.md` and `AQUA_COMMAND_CODEX_MASTER_PROMPT.md`. G5 working files excluded. **Verdict: HOLD for two Important findings; no Critical finding.**

1. **[P1 / Important] A truncated HTTP response permanently stalls recovery.** `src/lan/protocol.js:38–43` listens only for response `data`/`end`; it never rejects on `aborted`, response `error`, or premature `close`. After headers/body begin and the peer disconnects, the request timeout does not settle this promise. `agent.step`, `gateway.deliver`, or `dashboard.poll` consequently retains its `busy`/`polling` promise forever, blocking all later transfers/retries or status updates; service close also awaits it indefinitely. Retained source data stays safe initially, but export eventually stops at quota. `src/lan/telegram.js:15–19` has the same response lifecycle gap and can freeze all Gateway outbound work. Reject incomplete responses, preserve ambiguous-send retry semantics, and test a response terminated after headers/partial body. **Reproduction on frozen code:** one loopback-only HTTP server wrote 200/content-length 100 plus `{`, then destroyed its response. `requestJSON(..., {timeoutMs:100})` remained pending after 1000 ms. An injected Telegram request fake emitting partial `data`, `aborted`, and `close` also remained pending (zero response error listeners). No Telegram/external request occurred.

2. **[P2 / Important] Reused PIDs prevent durable services from recovering after reboot.** `src/lan/store.js:27–30` recognizes ownership solely by `process.kill(savedPid, 0)`. The persisted owner never gets cleared on orderly shutdown, and its stored `startedAt` is not compared with actual process identity. If that PID now belongs to an unrelated process after PID reuse/reboot, every restart rejects valid retained storage with `LAB_DATA_IN_USE`; the supervisor keeps failing until the unrelated process exits or metadata is manually changed. Use an exclusive ownership mechanism that expires with its actual process, or verify boot/start identity with a safe portable recovery path, preserving protection against genuinely concurrent writers. **No-network reproduction:** append one snapshot; persist an ancient owner record whose PID is now the unrelated review process; reopen the Store. `acquireOwner` returns `LAB_DATA_IN_USE`, while the retained snapshot remains present. Existing SIGKILL coverage only exercises an absent old PID.

The review found no additional Important defect in commit-before-ACK transaction ordering, exact ACK ID/digest matching, retained source replay, duplicate notification suppression, default dry-run egress, or fixed endpoint restrictions. Original SVG is unchanged in the committed range. Did not rerun the unchanged full suite or UI tests; parent-provided evidence remains 22 passing tests and three desktop viewports. Two physical hosts, real Telegram, Windows, and hardware power loss remain unverified. Planned G5 enrollment atomicity/read-only overrides/reset race fixes are outside this verdict and still require their own validation.
